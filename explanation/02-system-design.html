Design the system around the document lifecycle.

The architectural center is not the UI or the LLM. It is a trustworthy, traceable formatting job with clear inputs, rules, status, and output artifacts.

This is a layered design. Each layer has one primary reason to change: presentation, HTTP orchestration, workflow, policy, or document operations. That makes a complex feature explainable and testable in pieces.

Low-level design — the important boundaries

BoundaryResponsibilityWhy it is useful
Route handlersValidate inputs, map errors, create/read a job, return HTTP-safe responses.HTTP behavior stays out of document and AI logic.
Rule engineNormalizes standard, semi-custom and full-custom rules into one validated schema.Downstream code sees one contract regardless of rule source.
Agent factories + crewAssign discrete LLM responsibilities and control sequential context passing.Prompts are narrower, outputs have a clear owner, failures are easier to isolate.
Deterministic toolsExtract text/media, write DOCX, calculate checks and scores.Replaces probabilistic answers with exact behavior where possible.
Artifact layerStores input, intermediate report, final DOCX/PDF and provides download/preview.Creates a reviewable audit trail for the user.

Why sequential agents?

Parsing must precede transformation because the formatter needs structure; transformation must precede final validation because validation evaluates the output. The pipeline therefore uses a sequential dependency chain, like a document production line. Parallelism is appropriate within a stage only for independent work—for example, independent deterministic checks or media extraction.

Defensible choice: agents are not used just to sound advanced. The feature involves ambiguous academic structure, many heterogeneous rules and a user-facing explanation. A staged flow constrains the model’s task and leaves deterministic enforcement to code.

The API becomes stateless: it records a job transactionally and enqueues work; workers update progress/events and save artifacts. This lets API replicas scale independently from CPU/LLM-heavy workers. A user reconnecting after a restart can still inspect their job.

Reliability and security design

Idempotency

Hash input + rule version + formatter version. Repeat requests should reuse a completed result rather than create duplicate LLM jobs.

Observability

Give every request/job a correlation ID. Track stage duration, model tokens/cost, retries, failure reason, compliance deltas and download outcomes.

Data protection

Manuscripts may be unpublished. Encrypt storage, use short retention, restrict signed URLs, redact logs, state LLM data handling, and delete on user request.

Safe files

Allowlist formats, enforce size quotas, scan uploaded files, never trust names/paths, and isolate conversion processes with resource limits.

How to defend the evolution

Question: “Why didn’t you start with Kafka, Kubernetes and microservices?”

“The initial workload is a bounded document-processing flow, so a modular monolith minimizes operational overhead and accelerates validation. The boundaries already separate API, rule engine, pipeline and document tools. We would extract workers and add queue/object/database infrastructure when concurrency, durability or multi-user requirements demand it—not before.”
