React: the UI layer

React is a declarative component library. You describe the UI that should exist for a given state; React updates the browser DOM when state changes. This project’s App.jsx holds workflow state and composes specialized components—upload, configuration, progress, editor, score and results—around it.

Why React fits

A formatting workflow has many changing states: selected file, journal, overrides, progress, report and errors. Components make those states visible and reusable; hooks such as useState and useEffect handle local state and polling side effects.

Design discipline

Keep server data separate from transient UI state. As complexity grows, model the workflow as an explicit finite-state machine or reducer, cancel requests on unmount, and avoid putting long orchestration logic in one giant component.

Vite: the frontend toolchain

Vite is not a UI framework. It runs the development server with fast hot-module replacement and produces optimized static assets for production. It is a good choice for this SPA because the application does not require server-side rendering or backend-for-frontend behavior today.

Next.js: why people ask about it—and the honest answer

Next.js is a React framework that adds conventions for routing, server rendering, data fetching and server-side capabilities. This project uses Vite, not Next.js. That is reasonable because the application is an authenticated workflow/tool rather than an SEO-led content site, and FastAPI already owns the backend.

FastAPI: the API layer

FastAPI maps HTTP methods and paths to Python functions using decorators such as @app.post("/upload"). Type hints and framework integrations support validation and generated OpenAPI documentation. Here it is the boundary that receives multipart files, protects the pipeline with validation, dispatches background work and returns status/artifacts.

Why FastAPI fits

Python matches the document libraries and AI ecosystem. Its async-friendly API model is useful for network and file workflows, while clear route declarations make the contract discoverable.

Important distinction

async def does not automatically make CPU-heavy or blocking library calls scalable. Long document/LLM work should move to worker processes/queues under load.

CrewAI + Gemini: reasoning, not the database of truth

CrewAI coordinates task-specialized agents. Gemini supplies language-model inference for interpretation and transformation. The architecture should treat model output as untrusted structured input: validate it against a schema, normalize missing fields, attach rules/references, and prefer deterministic tools for math, patterns, ordering and document construction.

PostgreSQL: the recommended production system of record

PostgreSQL is a relational database. It stores data in tables connected by foreign keys and protects invariants with transactions, constraints and indexes. It is a strong production choice for this platform because users, documents, jobs, rule versions, permissions, audit events and payments are naturally related entities that benefit from consistency.

Use a transaction to create a job and its initial event together. Index format_jobs(owner_id, created_at) for dashboards and state for workers. JSONB is useful for evolving report payloads, but core queryable business facts should remain typed columns.

Why not MongoDB as the primary store?

MongoDB stores document-shaped records and supports flexible schemas. It could work for raw rule payloads, LLM outputs or a fast prototype. But this product’s central operations involve relationships and guarantees: a user owns documents; a document has many jobs; a job has events and artifacts; retention and billing must be correct. PostgreSQL handles joins, constraints and transactions naturally while still offering JSONB for flexible data.

If we chose MongoDB: embed a job’s report/events when they are read together; reference documents/users when they grow independently; add indexes for owner/status/time. We would still need careful transactional workflow design and strong schema validation. The decision is workload-driven, not ideological.
